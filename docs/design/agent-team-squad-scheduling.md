# 综合客服组、客服小组与排班联动设计

> 状态：已实现并完成定向验证  
> 负责分支：`codex/customer-audit`  
> 日期：2026-07-13

## 1. 目标

在不推翻现有客服组、门店员工归属、派单池和排班页面的前提下，将现有 `AgentTeam` 明确为综合客服组，并在组内增加可复用的客服小组。

```text
综合客服组
├── 客服一组
├── 客服二组
└── 机动小组
```

- 综合客服组负责业务责任、门店员工服务范围、权限、任务池和派单策略。
- 客服小组负责组内人员组合，不独立绑定门店员工，不形成平行任务池。
- 排班决定某个时间段由哪个客服小组值班。
- 会话始终只属于一个综合客服组；派单只生成一条 Assignment。

## 2. 当前阶段边界

### 本期实现

- 一个客服档案仍只属于一个综合客服组。
- 一个客服可以加入所属综合客服组内的多个客服小组。
- 客服小组成员必须来自所属综合客服组。
- 客服小组创建后不允许迁移到其他综合客服组；需要调整时应清理排班后重建。
- 门店员工和企微实例继续只归属综合客服组。
- 同一综合客服组同一时间只允许一条有效排班。
- 排班可指定客服小组；未指定时表示全组值班，兼容历史数据。
- 新人工任务从当前值班小组成员中选择客服。
- 已派发会话不因班次结束自动换人；待派发任务由新班次继续处理。

### 本期不实现

- 客服跨综合客服组多归属。
- 门店员工同时绑定多个综合客服组。
- 同一综合客服组多个小组并行值班。
- 自动交接已在处理的会话。
- 小组独立权限、独立服务范围、独立任务池或独立派单规则。

## 3. 数据模型

### AgentTeamSquad

客服小组主档案：

- `ID`
- `TeamID`：所属综合客服组
- `Name`
- `LeaderUserID`：小组负责人，可为空
- `Status`
- `Remark`
- 审计字段

同一综合客服组内小组名称唯一。

### AgentTeamSquadMember

客服小组成员关系：

- `ID`
- `SquadID`
- `AgentProfileID`
- `Status`
- 审计字段

同一客服档案与同一小组只允许一条有效关系。客服可以加入所属综合客服组内的多个小组。

### AgentTeamSchedule

新增兼容字段：

- `SquadID`：默认 `0`；`0` 表示全组值班，正数表示指定小组值班。

已有排班不需要 DML 迁移，AutoMigrate 后继续保持全组值班语义。

### ConversationAssignment

新增：

- `SquadID`：记录自动或手动派发时采用的值班小组快照，默认 `0`。

`Conversation.CurrentTeamID` 继续记录综合客服组，不新增小组级会话归属。

## 4. 派单规则

```text
人工任务进入综合客服组
→ 查询当前有效排班
→ 排班 squadId > 0：候选人为该小组有效成员
→ 排班 squadId = 0：候选人为综合客服组全部客服
→ 执行现有启用、自动接单、在线、并发、负载、优先级过滤
→ 生成唯一 Assignment，并记录 squadId
```

- 同一客服出现在多个来源时必须按客服档案去重。
- 客服总负载继续按用户全局计算，不按小组拆分。
- 指定小组无有效成员时，任务保留在综合客服组待派发池，不静默扩大到全组。
- 停用小组不参与派单；存在当前或未来排班时不允许停用或删除小组。
- 组长手动派发可以覆盖当前值班小组，但会话已有综合客服组归属时目标客服必须仍属于该综合组，并在事件理由中记录人工调度。

## 5. 页面设计

### 客服档案页

右侧增加视图切换：

```text
[客服成员] [小组编排] [服务范围]
```

- 客服成员：保留当前完整表格和 CRUD。
- 小组编排：左侧为综合客服组全部客服，右侧为小组容器。
- 服务范围：复用现有门店员工纳管信息，不重复建设入口。

小组编排行为：

- 客服条目前显示拖拽手柄。
- 拖入小组表示加入，不从综合客服组成员池移除。
- 拖拽预览通过页面级 `DragOverlay` 脱离资源池滚动容器；原位置只保留半透明占位，拖动过程不触发容器自动滚动。
- 小组落点按鼠标指针所在容器判定，避免相邻小组按条目重叠面积误判。
- 拖入后立即保存，并提供撤销。
- 小组成员可单独移除，不删除客服档案。
- 支持勾选多个客服后批量加入小组，移动端不依赖拖拽。
- 管理员和可管理该综合客服组的组长可编辑；其他用户只读。

### 左侧客服组

客服组三点菜单增加“增设客服小组”。小组编排视图同时提供可见的“新建小组”按钮，两个入口打开同一弹窗。

左侧客服组只显示小组数量，不展开小组树，避免占用导航宽度。

### 排班页

创建和编辑顺序：

```text
综合客服组 → 客服小组（可选，全组值班）→ 开始时间 → 结束时间
```

排班列表和日历显示综合客服组、小组名称及值班状态。点击客服小组的排班入口时，排班页预选对应综合客服组和小组。

## 6. 权限

- 查看小组复用 `agentTeam.view`。
- 创建小组复用 `agentTeam.create`。
- 编辑成员、小组负责人和状态复用 `agentTeam.update`。
- 删除小组复用 `agentTeam.delete`。
- 排班继续使用 `agentTeamSchedule.*`。
- 数据范围继续由 `AgentTeamScopeService.CanManageTeam` 判定，不新增平行权限体系。

## 7. 兼容与回滚

- `AgentProfile.TeamID`、`StoreStaffBinding.AgentTeamID`、`WxWorkProtocolInstance.AgentTeamID` 和 `Conversation.CurrentTeamID` 语义不变。
- 历史排班 `SquadID=0`，行为与当前一致。
- 删除或禁用小组前必须检查未来有效排班；存在排班时禁止删除。
- 回滚前端小组功能不会影响综合客服组、门店员工归属和历史会话。
- 回滚派单筛选时，`SquadID` 可保留为审计字段，不影响旧代码读取。

## 9. 实施结果

### 后端

- 新增 `AgentTeamSquad`、`AgentTeamSquadMember` 并加入 AutoMigrate，无 DML migration。
- `AgentTeamSchedule.SquadID` 与 `ConversationAssignment.SquadID` 均以 `0` 保持历史全组语义。
- 小组接口挂在现有 `/api/dashboard/agent-team/squad/*` 下，复用 `agentTeam.*` 权限与 `AgentTeamScopeService` 数据范围。
- 客服跨综合组移动、删除客服档案、删除综合客服组时增加有效小组关系保护。
- 小组归属创建后固定；当前或未来排班未清理前禁止停用或删除，派单候选只读取启用小组。
- 会话自动派发、人工转接流程里的自动分配、派单工作台规则推荐与规则自动派发统一读取当前值班小组。
- 主管手动派发仍可在会话所属综合客服组范围内覆盖值班小组，Assignment 的 `SquadID=0` 明确表示人工未指定小组。

### 前端

- 客服档案页保留原成员 CRUD，增加“客服成员 / 小组编排 / 服务范围”三个职责明确的视图。
- 小组编排采用左侧综合组客服资源池、右侧小组容器；拖拽表示加入，资源池不移除成员。
- 支持复选批量加入、单人移除、即时保存、撤销、新建、编辑、删除和跳转排班。
- 左侧客服组三点菜单提供“增设客服小组”，列表只显示小组数量，不展开树。
- 单条排班和批量排班均支持选择小组；批量多综合组时强制全组值班。
- 排班列表和日历显示小组名称；从小组编排跳转时预选综合组、小组并打开新建排班。

## 10. 合并与回滚

- 与 `codex/ai-billing` 的高风险同文件为 `internal/models/models.go`、`internal/bootstrap/routes.go`、`web/lib/api/admin.ts`、中英文多语言文件，必须逐字段合并。
- 本功能不修改 AI runtime、模型调用、token 统计和计费口径。
- 建议合并顺序：小组数据契约/API → 排班和派单筛选 → 客服档案编排 UI → 排班 UI。
- 回滚 UI 不删除小组数据；回滚派单筛选可保留两个 `SquadID` 审计字段，历史 `0` 值不影响旧逻辑。
