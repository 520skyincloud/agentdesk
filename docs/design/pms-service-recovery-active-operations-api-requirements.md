# 微宝客服 PMS、服务补救与主动经营接口需求

**文档日期：** 2026-09-12
**用途：** 提供给 PMS、服务补救和营销系统开发方，作为接口设计与联调依据。
## 1. 项目目标

微宝客服需要通过统一的服务端适配层，安全使用 PMS、工单和经营数据，为客户提供：

- 订单、入住和离店信息查询
- 实时房态、库存和房间推荐依据
- 服务请求、工单和进展跟踪
- 投诉后的服务补救申请
- 基于客户同意的主动经营触达

所有接口必须返回结构化结果，并明确数据时间、来源、成功状态和失败原因。

## 2. PMS基础接口

### 2.1 认证与租户

需要提供：

- 登录接口
- Access Token 刷新接口
- Token 校验接口
- 酒店/租户列表或酒店 ID 配置接口
- 服务健康检查接口
- 错误码、限流、超时和时区说明

认证要求：

- 支持服务端安全认证
- Token 不得出现在客户回复、普通业务日志或模型上下文之外
- 明确 Token 有效期和刷新方式

### 2.2 订单综合查询

支持按以下条件查询当前及未来订单：

- 手机号
- 会员 ID
- 订单号
- 接待单号
- 房号

返回至少包含：

- 订单号、接待单号
- 入住人姓名（按权限脱敏）
- 房型
- 房号（按客户权限脱敏）
- 入住时间、离店时间
- 房费、应付金额、已付金额、待付金额
- 订单状态
- 渠道
- 创建时间和更新时间

### 2.3 预订单详情

当前文档已有：

```text
GET /admin-api/hpms/orderManage/reserveOrder/detail
```

需要明确：

- `reserveOrderId`
- `hotelId`
- 返回字段定义
- 订单状态枚举
- 预订单与接待单关联规则

### 2.4 接待单详情

当前文档已有：

```text
GET /admin-api/hpms/orderManage/receptOrder/detail
```

需要明确：

- `receptOrderId`
- 房号、房型
- 入住/离店时间
- 房费、应付、已收、待付
- 入住人信息
- 订单状态

### 2.5 订单每日明细

需要提供：

- 每日房价明细
- 每日订单状态
- 早餐及其他权益
- 每日明细 ID
- 已消费/不可修改标记
- 预订单和接待单明细关联

该接口是修改价格和执行后核验的前置依赖。

### 2.6 实时房态

当前文档已有：

```text
GET /admin-api/hpms/roomDetails/realTimeRoomStatus/select
```

支持查询：

- 房号
- 住客
- 手机号
- 订单号
- 房型
- 楼层
- 房态

返回至少包含：

- 房号
- 房型
- 楼栋
- 楼层
- 空净、空脏、住净、住脏
- 维修状态
- 锁房状态
- 占用状态
- 数据更新时间

### 2.7 房型库存和房价

当前文档已有：

```text
GET /admin-api/hpms/changeInventory/query
```

需要返回指定日期范围内：

- 房型
- 日期
- 已售数
- 可售数
- 占房数
- 维修数
- 超售数
- 已售率
- 可售率
- 当前价格

空价格必须明确返回为空，不得解释为免费或零元。

### 2.8 可分配房间查询

需要提供按入住区间、房型和房态查询可分配房间：

- 入住日期
- 离店日期
- 房型
- 房间状态
- 是否已被占用

返回：

- 可用房号
- 房型
- 楼栋
- 楼层
- 净/脏状态
- 维修/锁房状态
- 当前占用状态

### 2.9 房间属性查询

如 PMS 有数据，需要提供：

- 高楼层
- 临街
- 靠电梯
- 朝向
- 无障碍
- 床型
- 窗户
- 面积

没有字段时必须返回“未配置”，不得由 AI 推测。

### 2.10 客户身份与订单归属验证

需要提供：

- 手机号验证
- 订单号验证
- 入住人信息验证
- 验证码验证（如支持）
- 客户与订单归属确认

验证成功后返回：

- 验证凭证或短期会话 ID
- 可展示字段范围
- 凭证有效期

未完成验证时，不得向客户直接返回完整房号、身份证、金额或内部备注。

### 2.11 会员信息查询

需要提供：

- 会员 ID
- 会员等级
- 会员状态
- 入住次数
- 积分
- 早餐权益
- 房型权益
- 可用升级权益

## 3. PMS写操作接口

生产环境默认关闭。所有接口必须支持：

- `operationId`
- 幂等键
- 操作人
- 来源会话 ID
- 来源消息 ID
- 版本号
- 并发冲突检测
- 执行结果查询
- 操作审计

### 3.1 升房报价与预览

返回：

- 原房型
- 目标房型
- 可用日期
- 差价
- 费用明细
- 预览有效期

预览接口不得实际修改订单。

### 3.2 修改房型

请求至少包含：

- 订单号
- 目标房型
- 操作原因
- 幂等键
- 版本号

### 3.3 分配房间

请求至少包含：

- 订单号
- 房型
- 目标房号
- 入住/离店时间
- 操作原因
- 幂等键

必须防止同一房间被同时分配。

### 3.4 在住换房

请求至少包含：

- 接待单号
- 原房号
- 目标房号
- 换房原因
- 幂等键
- 版本号

目标房间必须在执行时再次检查空净/空脏和未占用状态。

### 3.5 延迟退房

请求至少包含：

- 接待单号
- 新离店时间
- 增加费用
- 支付状态
- 操作原因
- 幂等键

### 3.6 修改价格

请求至少包含：

- 接待单号或订单号
- 每日明细 ID
- 新价格
- 修改原因
- 操作人
- 幂等键

当前已有部分接口：

```text
POST /admin-api/hpms/orderManage/receptOrder/dailyDetail/batchUpdatePrice
```

还需要每日价格明细查询接口，不能把预订单 `productDetailId` 当作每日明细 ID。

### 3.7 占房/锁房

请求至少包含：

- 房号
- 开始时间
- 结束时间
- 原因
- 操作人
- 幂等键

### 3.8 执行结果查询

所有写操作执行后必须支持按 `operationId` 查询：

- 排队中
- 执行中
- 成功
- 部分成功
- 失败
- 冲突
- 已重复执行

同时返回：

- 实际订单状态
- 实际房态
- 实际价格
- 失败原因
- 最后更新时间

只有结果查询确认成功后，微宝才能回复客户“已完成”。

## 4. 服务补救接口

### 4.1 工单创建

需要支持：

- 服务类型
- 问题描述
- 房号
- 数量
- 紧急程度
- 期望完成时间
- 客户 ID
- 会话 ID
- 来源消息 ID
- 幂等键

### 4.2 工单查询

返回：

- 工单号
- 当前状态
- 负责人
- 预计完成时间
- 最新进展
- 失败原因

### 4.3 工单进展回调

需要支持状态变化回调：

- 已受理
- 已分派
- 处理中
- 已完成
- 已取消
- 处理失败

回调至少包含：

- 工单号
- 状态
- 处理人
- 处理说明
- 更新时间

### 4.4 维修系统

需要提供：

- 报修创建
- 维修人员分派
- SLA 查询
- 维修结果
- 图片/附件
- 维修失败原因

### 4.5 补偿接口

需要分别提供：

- 优惠券模板查询
- 优惠券发放
- 优惠券发放结果查询
- 优惠券撤销
- 升房补偿申请与执行
- 延迟退房补偿申请与执行
- 退款/赔付申请
- 审批结果
- 执行结果
- 撤销接口

没有真实接口时，系统只能创建内部补偿申请，不能对客户承诺已发放或已赔付。

## 5. 主动经营接口

### 5.1 客户画像

需要提供：

- 会员等级
- 历史入住
- 消费记录
- 客户偏好
- 客户标签
- 服务历史

### 5.2 同意、退订与频控

需要支持：

- 同意营销
- 拒绝营销
- 退订
- 恢复订阅
- 同意来源
- 同意时间
- 最近触达时间
- 触达次数

退订必须立即生效。

### 5.3 权益和优惠券

需要提供：

- 可用权益查询
- 优惠券发放
- 领取状态
- 核销状态
- 过期时间

### 5.4 营销活动

需要提供：

- 活动查询
- 活动规则
- 有效期
- 适用门店
- 适用房型
- 活动库存

### 5.5 商品和服务

需要提供：

- 商品 SKU
- 商品名称
- 价格
- 库存
- 购买链接
- 适用门店
- 下单状态

### 5.6 触达结果回调

需要支持：

- 发送成功
- 发送失败
- 客户点击
- 客户退订
- 客户领取
- 客户核销

## 6. 统一安全要求

所有接口必须：

- 使用 HTTPS
- 支持服务端认证
- 明确租户和门店范围
- 支持幂等键
- 支持超时和重试规则
- 返回稳定错误码
- 不返回无关敏感字段
- 记录操作人和来源
- 支持审计查询

PMS 写操作额外要求：

- 默认关闭生产权限
- 人工明确授权
- 执行前再次读取最新状态
- 执行后再次查询确认
- 房间分配使用锁或版本控制
- 重复请求返回第一次执行结果

## 7. 第一阶段必须交付

优先交付以下接口：

1. 认证、Token 刷新和健康检查
2. 订单综合查询
3. 订单归属验证
4. 预订单详情
5. 接待单详情
6. 订单每日明细
7. 实时房态
8. 房型库存和房价
9. 可分配房间查询
10. 房间属性查询
11. 会员信息查询
12. 操作结果查询
13. 幂等和并发锁说明

第一阶段完成后，微宝可以稳定实现订单查询、房态查询、库存查询、房间推荐和升房判断，但不执行生产写操作。

## 8. 联调与验收

开发方需要提供：

- 接口文档
- 测试环境地址
- 测试酒店 ID
- 测试账号和密钥
- 测试订单
- 测试房间
- 成功和失败示例
- 错误码表
- 回调地址配置方式
- 限流和超时说明

验收必须覆盖：

- 正常订单查询
- 手机号无匹配
- 多订单匹配
- 客户归属验证失败
- 房态变化
- 库存变化
- 房间并发占用
- 重复写请求
- 写操作失败后读回
- PMS 超时和恢复
- 工单重复提交
- 客户退订后不再触达
