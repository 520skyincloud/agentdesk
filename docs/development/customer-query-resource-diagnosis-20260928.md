## 一、结论

不是单一模型识别问题，也不是所有 PMS 接口都坏了。已确认存在以下不同层次的问题：

1. 语义任务被提示词和本地纠正规则限制到错误数据源，会员公共规则不去查询会员系统。
2. 子问题虽然被拆开，但片段并非完整语义任务，主体没有继承。

## 三、逐项原因

### 1. 会员问题：不是拆开了就完成了

消息19816：“你们家会员有哪些，怎么升级，各项会员权益又有哪些”。

### 2. 换房反复问日期：是错误归类，不是客户没提供

- 该函数的接口失败分支没有覆盖认证/权限失败，导致进入错误追问。

因此，不能只再加一句提示词“记住日期”，也不能只增加一个403关键词分支。

- 配置一致性：PMS详情和已登录后台属于“丽驻智慧公寓（政务区省立医院南区店）”，客服19811发的是“丽斯未来酒店-合肥南七店”。可能为有意测试绑定，但目前两个来源酒店不同是事实；正式混合回答前必须明确绑定，不能默认同一家。

## 四、结构性实施方案

### 单一运行链路

客户原话与当前会话目标
→ 一次语义解析（完整任务、主题、补充/纠正/选择关系）
→ 现有Executor按事实依赖选择知识/PMS/资源
→ 查询与资源准备，产出结构化结果
→ Generate按已知事实和当前目标自然回答
→ Commit
→ Outbox
→ 独立记录实际发送结果。

不新增平行Agent、二次语义裁判或另一套消息状态机。

### 1. 统一任务与上下文

- 语义任务不是任意字符片段。保留原话/sourceRefs，并在同一次Intent解析中形成完整resolvedText，例如“酒店有哪些会员等级”“这些等级如何升级”“各级有什么权益”。
- 共用本轮会员主题和事实查询，不为三个相关问法重复取同一数据。
- 公共会员规则查询不需要客户手机号；个人等级、剩余资格等才使用已有手机号定位个人。
- 当前目标、明确手机号、已定位订单、日期来源、待补充字段和选择来源沿用现有上下文结构；不无限拼接历史。
- 只有真实缺少的输入才能补问。接口失败不能把已提供日期、手机号清空。
- 客户纠正使受影响旧事实失效；订单退房后保留历史查询用途，但不再作为可换房/续住的当前在住单。

### 2. 按业务依赖查询，不依赖FAQ命中决定能否查PMS

- 订单事实、会员个人资料、等级目录、等级权益、房态、价格和门店政策各有数据来源。
- 查询公共会员体系时使用真实等级目录及详情；先核实已有后台接口是否适合服务端授权接入，再确认协议和字段。未确认前标记能力缺口，不猜URL或写死等级。
- 一次换房评估：定位有效订单 → 确定待换剩余入住区间/客户另指定区间 → 并行查库存、具体房间、适用权益 → 必要时补查关联预订单价格 → 汇总方案。
- 查询失败只影响依赖它的结论，已经证实的会员/房型信息仍可回答；不拿一个失败覆盖整轮结果。
- 同一轮相同门店、同一参数查询共享结果，避免库存、可分配房和差价各自重复请求基础数据。

### 3. 用结构化结果替代错误文案推断

复用现有PMS步骤结果和任务状态，扩展明确原因，不新增业务状态机：

- success：已得到事实。
- empty：当前查询范围内没有匹配。
- needs_input：具体缺少哪些客户字段及来源。
- denied：认证或权限问题，客户补日期不能解决。
- invalid_state：订单状态不适用，如已退房不能续住。
- partial：部分字段缺失，如目标报价为空。
- unavailable：连接/超时/外部服务故障。

保留脱敏后的operation、HTTP状态、业务code、错误类别、耗时、查询时间和配置来源标识；不保留Token或整店住客原文。

删除依靠“missing文字包含日期/价格”等决定业务路径的分支。Generate只表达这些结果，不重新决定查询是否成功。

### 4. 资源发送基于已解析意图和实际产物

- 商品/客房服务区分由现有语义解析负责；移除下游重复购买关键词门。
- 下游只检查资源绑定、门店、协议字段、产物是否成功准备、发送幂等。
- 复用ActionLedger：requested不能当作prepared，更不能当作sent。资源未准备成功不得走空回复的direct commit。
- 商品卡成功准备：进入原Commit/Outbox；失败：保留原因并给客户自然、真实的文字说明，不静默，也不声称已发。
- 混合问题不能因为卡片失败阻断文字回答；重复回调不能重复发卡。

### 5. 价格、房间和状态采用同一事实口径

- 接待单确定身份、关联预订单确定相应产品的逐日费用，避免多房金额混入。
- 目标报价必须有适用日期、房型、币种、计价口径；缺少时只说明已确认的可选房间和暂不能确认的费用。
- 会员价、免费升房资格、补救减免分别判断，不把会员折扣直接变成免费升房。
- 区分自然日、营业日、房态快照、计划离店、实际离店；已结束区间不拿今天房态判断可用。
- 只读阶段不说已换房、已续住、已锁房。
- 门店绑定不一致作为运维配置问题解决，不让模型凭酒店名字自由选择另一门店。

### 6. 回复与速度

- 回复聚焦客户当前目标，不倾倒PMS字段和订单全量信息。
- 同一原因造成多个子题失败时合并一次说明，但保留各题已知答案；不同含义不能因句子相似被删除。
- 优先问能推进当前目标的一个字段，不重复索取已知信息，不默认转人工。
- 知识部分走原Judge；纯PMS或已准备好的资源不额外等无关知识判断。
- 查询按依赖并行、同轮去重；分别衡量Intent、检索、Judge、Generate、Commit、投递，不能用“程序已完成”替代客户等待时长。

## 五、实施顺序与验收
